Chapter 2: The physical Design

These are the materials I used for this project:

  • Arduino uno R3
  • ZS-040 bluetooth chip
  • 2 stepper motors with 2 A4988 drivers
  • AS5600 encoder
  • Power bank
  • 18V Milwaukee drill battery

The first part was actually making the motor move but theres infinite tutorials online for that so I'm gonna gloss over it.

After making the motor move, my first design looked like this:

Where the raised borders near the top would contain the second motor to actually point in a direction.

However, this issue had a major flaw that I didn't see. It was the fact that when the motor spinned, the top plate combined with the motor had a lot of inertia. And so, the hole in the center that fit around the shaft of the motor became loose.

So why is this bad? It was because I was counting the steps I sent to the motor, not the actual rotation that moved. So the computer would say "yup, I turned 90 degrees" but in reality, the disk slipped and it only turned 45 degrees. This would only worsen over time so I had to change designs.

So my second design looked like this:

This design actually incoporates an encoder on the side so that I could actually measure how much it spun.

Now, why is it on a completly different "island" from the motor? Well, the main reason was because I couldn't find a good way to put the encoder on the motor, so I just transfered the rotational force from the first disk onto the second disk where I could measure it. Then I can just fix it in software by inverting the tracked amount.

Also, the main reason why I made the second disk the same size was because it was easy to model the teeth. I could've made it smaller and fixed it in software but that sounded like too much work. So I just waited for like 3 more hours for it to print.

Chapter 3: Linking the phone

So no matter where I searched, I could not find an app that could send both the azimuth and the pitch at the same time. So what I did was I built my own app using MIT app inventor. Now this website is basically scratch but with extra blocks so I just used that.

On the surface, it seems simple. Just find the phone’s direction that it's pointing in and then copy the movements, but how do you actually find the direction? I settled on using the gyroscope of the phone and something called the “orientation sensor”.

  • The gyroscope provides angular velocity, so we can just take the integral to find where we are actually pointing in.
  • The orientation sensor is built into an android phone which essentially works as a compass by combining the magnetic field of the earth and the accelerometer to figure out which way is “down” (center of the earth) to find the direction relative to north.

By combining these 2 sensors with a complementary filter, we can measure pretty accurately which direction it's pointing in.

Note: a complementary filter works by combining basically the fast but slightly inaccurate angle from the gyroscope with the slow but accurate angle from the orientation sensor.

Chapter 4: Limitations

As you see in the video, it’s kind of choppy. This is mainly because I cannot send infinite amounts of data through bluetooth because it will get “clogged”. Think of putting too much toilet paper down a toilet and now you have to wait a long time for it to slowly clear up. Same thing here.

If you also look in the video, why is there a tape measurer on there? It was because the right gear is actually really light and I hoped it would be held down by gravity. But gravity couldn’t win so I used a tape measurer (the first weight I saw) and just slapped it on there.
